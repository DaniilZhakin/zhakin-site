# Реестр аналитических исследований — модель данных

> Статическая спецификация MVP. Это не действующая информационная система и не форма приёма клиентских данных. До внедрения backend, аутентификации, ролевой модели и аудита реальные сведения не вносить.

## Назначение

Единый реестр фиксирует происхождение, статус, методологию и ответственность за каждое исследование. Реестр должен обеспечивать воспроизводимость выводов и отделять подготовку материала от его проверки и публикации.

## Карточка исследования

| Поле | Тип / формат | Правило |
|---|---|---|
| Research ID | UUID / внутренний идентификатор | Не переиспользуется |
| Название | Строка | Кратко и предметно |
| Направление | Справочник | Макроэкономика, финансы, торговля, экспорт, промышленность, инфраструктура, технологии, безопасность, продовольственные рынки, социальная сфера |
| Заказчик / мандат | Ссылка на утверждённое поручение | Не создавать клиентский профиль без отдельного согласования |
| Владелец исследования | User ID | Назначенный аналитик |
| Дата среза | YYYY-MM-DD | Обязательна для рыночных и статистических данных |
| Период анализа | Диапазон дат | Указывать отдельно от даты подготовки |
| Источники | Реестр ссылок / документов | Источник, дата публикации, дата доступа, первичность, ограничения |
| Методология | Справочник + описание | Формулы, определения, единицы измерения, фильтры |
| Допущения и ограничения | Текст | Обязательны при существенном влиянии на результат |
| Reviewer | User ID | Не совпадает с автором для материалов высокого риска |
| Статус | Workflow enum | См. ниже |
| Версия | Семантическая / последовательная | Каждое существенное изменение фиксируется |
| Классификация | Public / Internal / Confidential / Restricted | По утверждённой политике доступа |
| Решение о публикации | Approval record | Отдельно от аналитического статуса |
| Audit trail | Неизменяемые события | Кто, что, когда изменил и на каком основании |

## Статусы

1. `draft` — подготовка.
2. `in_review` — передано на проверку.
3. `changes_requested` — требуются исправления.
4. `approved_internal` — разрешено внутреннее использование.
5. `approved_publication` — публикация отдельно одобрена уполномоченным лицом.
6. `published` — опубликовано с указанием URL и даты.
7. `archived` — выведено из активного оборота; история сохраняется.

Переходы статусов должны проверяться сервером. Клиентский интерфейс не является источником полномочий.

## Контроль качества

- Все существенные количественные выводы должны иметь воспроизводимый расчёт и ссылку на исходные данные.
- Для внешних данных фиксируются дата доступа, валюта, единицы измерения и метод преобразования.
- Проверяются арифметика, периодизация, сопоставимость, пропуски, дубли и конфликты источников.
- Прогнозы отделяются от фактов; сценарии — от базового случая.
- Изменения после review возвращают материал на повторную проверку.
- Публикация запрещена без отдельного approval record.

## Ролевая модель (проект)

- `analyst`: создаёт и редактирует собственные черновики.
- `reviewer`: проверяет методологию и доказательную базу, возвращает на доработку или рекомендует одобрение.
- `center_director`: назначает владельцев и утверждает внутреннее использование в рамках полномочий.
- `publication_approver`: отдельно разрешает публичное раскрытие.
- `auditor`: read-only доступ к карточкам и журналу событий.
- `platform_admin`: техническое администрирование без автоматического права утверждать содержание.

Ролевые полномочия должны быть минимальными, разделёнными и проверяться на сервере. Нельзя полагаться на скрытие кнопок в браузере.

## Минимальные критерии готовности MVP

- Уникальные идентификаторы и версии.
- Серверная авторизация каждого действия.
- Разделение доступа по роли, мандату и классификации.
- Неизменяемый журнал событий.
- Проверка ссылок и сохранение метаданных источника.
- Экспорт только с учётом классификации и approval.
- Тесты на горизонтальное повышение привилегий, повтор запроса, подмену владельца, обход статусов и утечку закрытых записей.

До выполнения критериев использовать только обезличенные демонстрационные записи.
