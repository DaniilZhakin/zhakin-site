# Контактный контур — архитектура

## Назначение

Контактный контур официального сайта должен обеспечивать безопасный переход от посетителя к структурированному обращению без ложного ощущения, что данные уже переданы оператору.

## Текущее состояние

- `/reception.html` — безопасный конструктор обращения.
- Введённые данные не отправляются на сервер и не сохраняются.
- Honeypot-защита снижает риск простого автоматического спама.
- Готовое обращение можно скопировать с мобильного устройства.
- Канал фактической доставки обращения пока не подключён.

## Целевая цепочка

`Посетитель → Приёмная → Валидация → Формирование обращения → Выбор официального канала → Доставка → Подтверждение`

## Принципы

1. Не заявлять об успешной доставке, если серверный канал не подтвердил приём.
2. Не хранить содержание обращения без отдельного основания и политики хранения.
3. Не запрашивать лишние персональные и платёжные данные.
4. Разделять публичный интерфейс, транспорт доставки и внутреннюю обработку.
5. Для каждого канала иметь явный статус: `ACTIVE`, `PLANNED` или `DISABLED`.
6. Любой внешний канал должен быть подтверждён владельцем сайта до публикации.

## Следующий технический шаг

После подтверждения конкретного официального канала подключается адаптер доставки. Интерфейс приёмной при этом не меняется: форма остаётся единым входом, а транспорт становится заменяемым модулем.

Рекомендуемая модель адаптера:

- `contact-channel` — описание канала;
- `contact-router` — выбор доступного канала;
- `contact-delivery` — передача обращения;
- `contact-status` — подтверждение результата;
- `contact-audit` — минимальный технический журнал без содержания обращения.

До появления реального серверного транспорта сайт сохраняет безопасный режим конструктора и не имитирует отправку.
