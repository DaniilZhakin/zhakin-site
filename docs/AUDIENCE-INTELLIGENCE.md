# 2.8 — Audience Intelligence

## Назначение

Audience Intelligence добавляет на сайт наблюдаемую модель интереса аудитории без скрытой идентификации посетителей.

На первом этапе слой фиксирует только технические и навигационные события в браузере посетителя. Данные не отправляются на внешний сервер и не содержат IP-адресов, fingerprinting, текста форм или иных персональных данных.

## События v1

- `page_view` — открытие страницы;
- `navigation_click` — переход по навигации или якорю;
- `menu_toggle` — открытие/закрытие мобильного меню;
- `outbound_click` — переход на внешний ресурс.

Каждое событие содержит только тип, текущий путь, время и минимальный технический контекст.

## Хранение

События временно хранятся в `sessionStorage` текущего браузера, максимум 50 последних событий. Если хранилище недоступно, сайт продолжает работать без изменений.

Это сознательная архитектурная граница: GitHub Pages не является сервером для безопасного централизованного сбора аналитики.

## Следующий этап

Для реального агрегированного Audience Intelligence потребуется отдельный privacy-first collector или аналитическая платформа. Только после выбора такого канала можно строить централизованные метрики:

`посещения → интерес к разделу → глубина взаимодействия → исходящий переход → обращение`

Контактные обращения должны оставаться отдельным контуром и не смешиваться автоматически с анонимной статистикой посещений.

## Принцип

**Сначала минимизация данных и архитектурная прозрачность, затем аналитика.**

Слой не принимает решений о личности посетителя и не пытается деанонимизировать аудиторию.
